# Security, correctness, and performance review — 5 October 2026

The review prioritised public input handling, API authorization, uploaded active
content, recursive content structures, and cache correctness. Changes are in the
local checkout. The deployed site was checked read-only; it was not updated.

## Changes

| Area                     | Verified problem                                                                                                                                                                    | Result                                                                                                                                                                                                   |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Content API              | Anonymous reads included published posts whose post type was private.                                                                                                               | Public reads require a public post type; privileged reads require both a token's `read` ability and the user's `view posts` permission.                                                                  |
| Token abilities          | A write-only token inherited access to unpublished content.                                                                                                                         | Read privileges are checked independently of write privileges. Public published content remains accessible.                                                                                              |
| Page publishing          | Sending the page type's slug (`pages`) instead of its name (`page`) bypassed the page-specific publishing permission.                                                               | Publishing checks use the resolved post type.                                                                                                                                                            |
| Menu links               | Base and translated URLs accepted executable schemes. Existing unsafe URLs were passed straight to HTML and JSON consumers.                                                         | Input validation rejects unsafe schemes; URL resolution also neutralizes unsafe historical records. Relative links, HTTP(S), mail and telephone links remain supported.                                  |
| SVG uploads              | A regex missed XML entity-encoded script URLs and SVG animation that changes link targets.                                                                                          | XML is parsed without external loading or entity expansion. A static SVG element allowlist rejects scripts, event attributes, animation, foreign namespaces, DTDs, external stylesheets and unsafe URLs. |
| Menu hierarchy           | Item updates could create cycles, excessive nesting and cross-menu parents. The request missed Laravel's snake-case route parameter.                                                | Both parameter spellings resolve correctly; proposed trees are checked in one query, including the depth of moved descendants. Existing items remain in their menu.                                      |
| Media folders            | `{folder}` did not match the controller's `$bucket` binding, so updates/deletes did not load the requested record.                                                                  | Controller parameters match the resource route. Updates, deletes and missing-folder responses have regression coverage.                                                                                  |
| Folder hierarchy         | Moving a folder into itself or a descendant could create cycles.                                                                                                                    | Ancestor checks reject cyclic moves.                                                                                                                                                                     |
| Taxonomy hierarchy       | The request missed the resource route's `taxonomy_term` parameter; self-parent checks did not run correctly. Descendant cycles and cross-taxonomy subtree moves were also possible. | Route binding is resolved consistently, cyclic moves are rejected, and terms with children remain in their taxonomy.                                                                                     |
| Page cache privacy       | Cache keys omitted the visitor's language and sidebar preference. Guest plugin/session data could be shared through a public page.                                                  | Keys include language and sidebar state. Personal session data bypasses caching; responses are rechecked after rendering and responses with cookies or `no-store` are not stored.                        |
| Cache invalidation       | Concurrent read/increment/write operations could reuse an invalidation generation.                                                                                                  | Unique generations replace counters for page, post and post-type caches.                                                                                                                                 |
| Cache performance        | Every audit entry, autosave and revision invalidated all public pages, including failed-login audit entries.                                                                        | Bookkeeping and unsaved drafts preserve the public page cache; saved content still invalidates it immediately.                                                                                           |
| Query input              | Array-valued search and language parameters could trigger PHP type errors.                                                                                                          | Search input is validated; malformed language preferences are ignored.                                                                                                                                   |
| Development dependencies | `lint-staged` pulled in the vulnerable `braces`/`micromatch` chain.                                                                                                                 | Updated to `lint-staged` 17.6.0, removing the affected dependency chain. See the [GitHub advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).                                                   |

Static SVG uploads intentionally exclude animation and embedded stylesheet elements.
SVG uploads remain opt-in. Existing menu items cannot be transferred between menus
through the item update endpoint; this prevents leaving descendants in another menu.

## Verification

PHP validation ran in disposable containers on the VPS, using a separate source copy
and dependencies. SQLite used an in-memory database. PostgreSQL used a new container,
private Docker network and temporary database storage, without production volumes,
credentials or published ports. The source copy contained tracked files plus the
review changes, without local environment files or installed plugins.

The original PHP suite passed before changes: 468 tests on SQLite, with the existing
PostgreSQL-only search test skipped. New request-level tests cover rejected inputs,
access boundaries, working folder operations, static SVGs, cache privacy and cache
preservation during autosaves.

Frontend TypeScript, ESLint, formatting, 42 Vitest tests and the production build
passed. Both npm audit and Composer audit reported no advisories after the dependency
change. PHP style and static analysis passed during the review; the analysis baseline
was not expanded.

Live checks returned 200 for the homepage and `/health`, and 403 for `/.env` and
`/.git/config`. The queue worker's repeated exits were its configured maximum runtime,
followed by restarts. The deployed checkout differs from the reviewed local checkout.

## Scope

The review also inspected raw SQL, shell/process calls, content sanitization,
authorization policies and package extraction/download paths. No SQL injection was
identified in the inspected raw queries; user input was bound separately from SQL.
This was a targeted source review and regression test pass, not an exhaustive
penetration test. Installed third-party plugin code and browser end-to-end workflows
were outside this validation run. The SVG validator applies to new uploads; previously
uploaded SVG files were not rescanned. Temporary VPS test containers, their network
and the source/dependency copy were removed after verification.

Useful repeat checks:

```sh
php vendor/bin/pest
php vendor/bin/pest -c phpunit.pgsql.xml
php vendor/bin/pint --test
php vendor/bin/phpstan analyse --memory-limit=512M --no-progress
composer audit
npm audit --audit-level=high
npm run types
npx eslint . --quiet
npm run format:check
npm run test:js
npm run build
```

The PostgreSQL command requires a dedicated `modulo_test` database; the suite resets
its data. Keep test connections separate from any deployed database.
